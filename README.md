# AgriBiz

An agribusiness web application that connects smallholder farmers directly with buyers: households, hotels, schools and exporters. Farmers list produce for sale; buyers browse, search and order online; administrators approve accounts and listings and manage orders.

Built with **PHP (procedural, mysqli)**, **MySQL/MariaDB**, **HTML, CSS and JavaScript**. Runs on **XAMPP** (Apache + MySQL).

---

## Features

**Public website**
- Home, About Us, Produce Catalogue, Product Detail, Farmer Profiles, Contact Us
- Live search and category filter (updates as you type, no page reload)
- Add to cart without reloading the page
- Responsive layout for desktop and mobile

**Buyers**
- Register and log in
- Cart and checkout
- Order history and a printable / save-as-PDF receipt

**Farmers (dashboard)**
- Create, edit and remove produce listings (name, category, price, quantity, location, photo)
- Overview of listings, stock, orders received and sales
- Listings go live only after administrator approval

**Administrators (dashboard)**
- Approve farmer accounts and produce listings
- View all orders and move them through the order lifecycle
- Overview of pending approvals, orders, buyers and revenue

**Order lifecycle:** Placed → Confirmed → Dispatched → Delivered

## Installation (XAMPP on Windows)

1. **Copy the project** into XAMPP's web folder so the path is:
   `C:\xampp\htdocs\agribiz`
   (`index.php` must sit directly inside the `agribiz` folder. The folder name must be exactly `agribiz`.)
2. **Start XAMPP.** Open the XAMPP Control Panel and start **Apache** and **MySQL**.
3. **Create the database.**
   - Open `http://localhost/phpmyadmin`
   - Click **Import** → **Choose file** → select `schema.sql` → **Import**
   - This creates the `agribiz` database, all tables and the product categories.
4. **Open the site:** `http://localhost/agribiz/`

## How to use it (typical flow)

1. A farmer registers with the role **Farmer**.
2. The administrator logs in to the dashboard and approves the farmer under **Farmers awaiting approval**.
3. The farmer logs in to the dashboard and adds produce under **My listings**.
4. The administrator approves the listing under **Listings awaiting approval**. It now appears in the shop.
5. A buyer registers (buyers are approved automatically), adds produce to the cart and places an order.
6. The administrator moves the order through Confirmed → Dispatched → Delivered.
7. The buyer views the order under **My orders** and prints the receipt.

## Configuration

Settings are in `config.php`:

| Setting | Default | Notes |
|---|---|---|
| Database host | `localhost` | |
| Database user | `root` | XAMPP default |
| Database password | *(empty)* | XAMPP default |
| Database name | `agribiz` | Created by `schema.sql` |
| `BASE` | `/agribiz/` | URL path of the project. Change it if you rename the folder, or set it to `/` if the site runs at the domain root. |

**Environment variables:** this project does not need a `.env` file locally. For a public deployment, do not leave real database credentials in `config.php` inside Git. Read them from your host's environment variables instead, for example `getenv('DB_HOST')`, `getenv('DB_USER')`, `getenv('DB_PASS')` and `getenv('DB_NAME')`.

**Change the admin password:** in phpMyAdmin, open the `users` table and replace the admin row's `password` with a hash generated by PHP's `password_hash()`.

## Database

Tables: `users`, `categories`, `produce`, `orders`, `order_items`.

```
users (1) ──< produce >── (1) categories
users (1) ──< orders (1) ──< order_items >── (1) produce
```

- `users.role` is one of `farmer`, `buyer`, `admin`
- `users.approved` controls whether farmers can log in
- `produce.approved` controls whether a listing is visible in the shop
- `orders.status` is one of `Placed`, `Confirmed`, `Dispatched`, `Delivered`

## Security measures

- Prepared statements for all database queries (protects against SQL injection)
- Passwords hashed with `password_hash()` and checked with `password_verify()`
- Password rules: at least 8 characters with letters and numbers
- Session ID regenerated on login; login attempts limited (5 failures, then a 60 second wait)
- CSRF token on every form
- Output escaped with `htmlspecialchars()` (protects against XSS)
- Role checks on every dashboard page
- Client-side and server-side input validation
- Photo uploads checked by real file type and size (JPG, PNG, WebP, max 2 MB), renamed randomly, and PHP execution is disabled inside `uploads/`
- Stock is checked and reduced inside a database transaction at checkout

## Quick test checklist

| Test | Expected result |
|---|---|
| Register with password `abc` | Rejected: password too weak |
| Register with an email already used | Rejected: already registered |
| Log in with `' OR '1'='1` as the email | Rejected, no error shown |
| Log in as an unapproved farmer | "Awaiting administrator approval" |
| Open `dashboard/admin.php` while logged out | Redirected to dashboard login |
| Order more than the stock available | Order refused, stock unchanged |
| Upload a `.php` file as a photo | Rejected |
| Resize the browser to phone width | Menu collapses, layout stacks |

## Troubleshooting

- **Apache won't start:** another program is using port 80 (often Skype or IIS). Stop it, or change Apache's port and use `http://localhost:8080/agribiz/`.
- **"Database not found":** import `schema.sql` in phpMyAdmin.
- **Page shows PHP code or downloads:** open it through `http://localhost/...`, not by double-clicking the file.
- **Styles or links broken:** check the folder is named `agribiz`, or update `BASE` in `config.php`.
- **Photos won't upload:** make sure the `uploads/` folder exists and is writable.
- **Admin login fails on first visit:** refresh the login page once, then try again.

## Deployment notes

- Use a host that supports **PHP and MySQL** (shared hosting or a PHP-capable platform). Many free tiers do not.
- Import `schema.sql` into the host's database, then set the database details through environment variables or a private config file.
- Set `BASE` to match where the site lives.
- Enable HTTPS and force it.
- Change the default admin password.

## Known limitations

- The Contact Us form validates input but does not store or email messages yet.
- Payment is not integrated; orders are placed and fulfilled offline.
- Produce without a photo shows an illustration, not a real photo.
